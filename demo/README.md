## ★핵심 정직 결론
- **강화 프롬프트로도 C1/C2 모드붕괴는 안 깨졌다.** 실 LLM은 단일선택 강제 시 최빈답으로 수렴.
  → 프롬프트 엔지니어링만으론 분산붕괴를 못 잡는다(문서화된 구조적 한계).
- **해법**: 진짜 VS 분포표집(모델이 P(옵션) 분포를 내면 *내가* 표집; 모델의 choice를 신뢰하지 않음).
  현 데모는 스키마 단일선택이라 붕괴. ClaudeBackend._vs를 'dist에서 직접 표집'으로 강화하면 완화.
- **그럼에도** B2(C계열)·A2(접근성)·D1(외식절벽)·E1(T2방향)·B3(마찰)은 사전조사·이론과 정합하는
  현실적 텍스처를 냄. v0.3대로 방향은 🔴/🟡 인용금지, 텍스처는 생성적 가설.

## VS 분포표집으로 모드붕괴 해결 (추가)

`report_live100_vsfixed_9_4.md` — C1/C2/B1을 VS 분포표집으로 교체한 최종본.
- `live100_vs_dists.json` — 유형별 C1/C2/B1 분포('10명 중 몇 명')
- `responses_live100_vsfixed.csv` — 표집·패치 후 응답
재현: `python3 patch_vs.py <agent100.json> <dist100.json> <out.json> && python3 run_live.py <out.json>`

**해법 원리:** 모델에게 단일선택("어느 거?")을 시키면 최빈답으로 붕괴. 대신 "비슷한 10명이 어떻게
갈리나"를 물어 분포를 받고 **하니스가 표집**(모델 choice 불신) → 분산붕괴 방어. `ClaudeBackend._vs`에
이 방식을 영구 배선. 프롬프트 엔지니어링(힌트)으로는 안 됐지만 표집 아키텍처 변경으로 해결됨.
